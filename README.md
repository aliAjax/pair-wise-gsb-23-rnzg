# hxwl-09 半导体洁净室巡检

压差梯度与缓冲间通行闭环看板：房间登记走廊压差、相邻房间压差方向和缓冲间人数；
压差低于 5Pa、方向倒置或人数到两人时，通行申请停在待复核，填写依据并经班组长放行。

## 技术栈

React 19 + Vite + TypeScript + 纯 CSS（无第三方运行时依赖）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5109

## 业务闭环

1. **房间登记（数据层）**：房间编号 / 洁净等级 / 相对走廊压差 / 相邻房间编号 / 实测压差方向 / 梯度要求方向 / 所属缓冲间人数，支持新登记房间与新建缓冲间。
2. **规则判定（判定层，纯函数）**：
   - `LOW_CORRIDOR_PRESSURE` 走廊压差低于 5Pa
   - `DIRECTION_INVERTED` 实测方向与梯度要求方向倒置
   - `AIRLOCK_CAPACITY` 缓冲间人数达到两人
3. **通行申请**：无冲突自动放行；命中任一规则即停在「待复核」，申请时刻冻结压差/方向/人数与版本号快照。
4. **复核放行**：复核依据必填，仅班组长可放行；放行后房间数据与缓冲间人数冻结，已放行单不可重复放行。
5. **冻结补录**：冻结后修改必须填原因，只生成带原因的新版本，旧值完整保留在版本链；放行前修订直接更新、不留版本。
6. **跨班顺延**：A/B/C 三班轮换，交接时未复核的申请（含已顺延的）自动顺延至下一班并留顺延记录，可在下一班继续复核放行。
7. **刷新一致**：全部状态写入 `localStorage`（`hxwl-09.pressure-pass-loop.v1`），刷新后申请、放行版本与顺延状态一致；冲突清单实时列出房间、压差、人数和命中规则。

## 分层结构（数据、判定、页面分开）

```
src/
├── data/                  # 数据层：领域模型、种子数据、localStorage 仓储（唯一写入口）
│   ├── types.ts           #   RoomRegistration / Airlock / PassageApplication / 版本 / 顺延
│   ├── seed.ts            #   初始演示数据（含已放行、待复核、跨班顺延三种申请）
│   ├── repository.ts      #   发布订阅 + 持久化、冻结判定、登记/补录/申请/放行/交接动作
│   └── id.ts
├── rules/                 # 判定层：纯函数，不依赖存储与 DOM
│   ├── pressureRules.ts   #   5Pa 下限、方向倒置、两人上限，evaluate / evaluateAll
│   ├── shift.ts           #   班次推导（A/B/C、跨天）
│   └── workflow.ts        #   用例编排（申请、复核放行、交接）
└── ui/                    # 页面层：只读状态 + 调动作，不内置业务规则
    ├── ShiftBar.tsx       #   当前班次 / 角色切换 / 跨班交接
    ├── MetricCards.tsx    #   指标卡
    ├── ConflictBoard.tsx  #   冲突清单（房间、压差、人数、规则）
    ├── RoomRegistry.tsx   #   房间登记卡片、补录版本链、发起申请
    └── PassageDesk.tsx    #   申请列表、待复核填依据、放行冻结、顺延记录
```

页面角色（巡检员 / 厂务工程师 / 班组长）仅控制页面视角与按钮可用性；
切换到「班组长」才能在待复核（含顺延）申请上填写依据并放行。
